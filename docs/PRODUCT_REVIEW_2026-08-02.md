# 《荒原引擎》产品审查与迭代路线

> 2026-08-09 更新：本文记录的是 PixiJS 重构前的产品判断。运行时现已迁移到 PixiJS 8 全屏场景图；文中关于固定 `640x480` Canvas 与未来迁移 Phaser 的描述仅保留为历史背景。

审查日期：2026-08-02（2026-08-03 更新）
审查对象：Vue 3 + TypeScript 重构版及拉多区域第一纵切

## 1. 结论

当前版本已经从一次性网页 Demo 变成了可继续开发的游戏纵切：探索、室内、战斗、战车、商店、存档、键盘、手柄和触屏共用一套带类型的状态与规则层，拉多区域可以用于验证生产标准。

它仍不是内容完整、可发行的游戏。现阶段最大的风险不是 Canvas 性能，而是地图、美术、音乐和原创剧情缺少可规模化的制作源与验收流程。麦镇已经作为第二个手工城镇样本完成，用于验证不同轮廓、地标和功能分区；但 Phaser 3 + Tiled/LDtk、Aseprite 和 FamiStudio 管线仍未建立，因此不能据此批量复制其余城镇，否则只会扩大返工面。

另外，当前数据中的部分经典人名、地名与剧情骨架只可用于流程原型。正式发行前必须整体原创化，这是一项 P0 发行阻断，不是后期润色。

## 2. 本轮达到的基线

### 工程与交互

- `640x480` 逻辑舞台统一承载 Canvas 与 Vue UI，不再把网页显示尺寸锁死。
- PC 使用半档缩放；触屏按可用区域连续等比适配，并保持 nearest-neighbor 渲染。
- 已验收 `1366x768`、`1920x1080`、`2560x1440`、`390x844`、`844x390`。
- `390x844` 有效画面由 `320x240` 提升到 `388x291`；`844x390` 提升到 `520x390`，均无页面滚动溢出。
- 键盘、标准 Gamepad API、触屏方向键与 A/B 键覆盖同一输入协议；对话支持点击推进。
- 设置页已提供独立音乐/音效音量和慢/标准/快文本速度，经过校验后持久化到 `mmw_settings_v1`，启动时同步到音频总线与对话系统。

### 战斗表现

- 战斗环境分为荒野、森林、山地、城镇、洞窟、沙漠、终局设施七类，并由当前位置自动选择。
- 8 辆战车拥有独立炮塔、炮管、比例和配色配置；当前仍有共用底盘资产，不能视为最终战车美术。
- 探索战车已改为真正的俯视四向轮廓，八辆车分别使用履带/轮式/箱式底盘和标准炮塔、侦察炮塔、医疗舱、长炮、攻城炮、导弹舱、狼式炮塔、轨道炮配置，不再以上下方向复用侧视图。
- 战斗炮塔会随当前目标改变仰角，主炮、副炮与 S-E 具有不同后坐幅度；车体按 SP 分为完好、受损、危急与瘫痪状态，危急状态显示划痕、火焰和动态烟柱。
- 战斗 HUD 同时显示装甲片与车体 SP，并用黄/红状态色提示结构损伤，避免只显示装甲片掩盖车体危急状态。
- 主炮、副炮、S-E、徒步、敌方与道具使用不同弹道、节奏、命中、落空和爆炸反馈。
- 动态矩形坐标已统一落到整数像素，击杀动画结束前敌人不会提前灰化。
- 修复玩家行动后敌方无法接管回合、攻击日志延迟和战斗 UI 空状态竞态。

### 音乐与音频

- 10 首场景曲目均有一次性 intro 和正式 loop，不再是单小节无限重复。
- 城镇、宿屋、野外、普通战、赏金首战和终局战在速度、声部、延音和力度上有明确层次。
- 音乐与音效使用独立总线，音效总线降低到音乐的 `0.78`，减少战斗音效遮蔽。
- 玩家可分别调节音乐与音效音量，两个总线的设置互不覆盖；浏览器回归已验证设置跨界面即时生效。
- 主输出增加动态压缩/限幅，降低密集延音、重音和爆炸叠加时的削波风险。
- 当前 Web Audio 曲谱可用于玩法验证，但没有可交给作曲/音频人员持续制作的工程源，不能视为最终母带。

### 验证证据

- TypeScript、ESLint、Vitest 与生产构建均已纳入 `npm run check`。
- 当前自动化回归：10 个测试文件、90 项测试。
- 单文件离线构建保留，第三方素材署名已进入标题画面的“制作名单与素材许可”。
- 七类战斗背景与三种战车武器动画均已完成真实浏览器截图检查；森林、山地在生产页与离线预览中均通过。桌面与 `390x844`、`844x390` 移动视口的生产页控制台均无 warning/error，且无页面滚动溢出。
- 麦镇已在 `1280x720` 桌面与 `844x390` 横屏完成生产页检查；设置页在 `390x844` 竖屏无溢出，并实测音乐音量可由 `100%` 调至 `75%`。
- 战车四向、越野车/救护车/导弹车/红狼车/轨道炮车轮廓、危急烟火和战斗双耐久 HUD 已完成真实浏览器检查；`390x844` 画布为 `388x291`，`844x390` 为 `520x390`，均无页面溢出，控制台 warning/error 为 0。

## 3. 产品审查

| 维度     | 当前判断                           | 主要缺口                                               |
| -------- | ---------------------------------- | ------------------------------------------------------ |
| 核心循环 | 拉多纵切可验证                     | 后续区域仍以数据可跑通为主，缺少逐区域内容验收         |
| 探索     | 拉多、麦镇已有不同的手工布局       | 其余城镇重复布局，环境叙事、支线与地标不足             |
| 战车     | 四向轮廓、瞄准、后坐与受损反馈成立 | 仍需原创逐帧资产、履带动画、部件损坏与瘫痪残骸状态     |
| 战斗     | 回合与表现层已分离，反馈明显改善   | 敌人行为差异、状态效果、弱点和 Boss 阶段仍浅           |
| UI/输入  | PC、触屏、手柄及基础设置可用       | 缺少键位/手柄重映射与更完整的无障碍选项                |
| 美术     | 拉多和部分战斗素材达到纵切可读性   | 风格仍混合程序绘制与多来源素材，未形成统一原创资产集   |
| 音乐     | 场景层次和循环结构成立             | 需要 FamiStudio 工程、真机试听、响度标准和最终导出     |
| 存档     | 旧坐标兼容、单存档可用             | 缺少多槽、版本迁移表、损坏恢复和跨设备方案             |
| 发行     | 单 HTML 可离线运行，许可台账完整   | 原型剧情原创化、完整归属文本、内容量与兼容性尚未过门槛 |

## 4. 优先级

### P0：批量扩展正式区域前必须完成

1. **原创内容圣经**：重做世界观、角色、城镇、组织、主线事件和对白命名；建立禁用的临时原型名清单。
2. **地图生产管线**：接入 Phaser 3 与 Tiled 或 LDtk，落实 `ground/path/below/collision/trigger/entity/above/light` 图层协议，并保持现有状态、战斗和存档 API 不变。
3. **原创资产规范**：用 Aseprite 建立角色、敌人、8 辆战车、建筑与特效的源文件、调色板、锚点、帧命名和导出脚本。
4. **正式音乐源**：把曲目迁移到 FamiStudio，保留 intro/loop 标记，定义场景切换、响度、峰值和音效遮蔽验收。
5. **完整纵切走查**：从新游戏到取得 NO.1、回镇服务、战斗、存档、读档完成连续实机回归，并覆盖移动端真实设备。

### P1：第二个内容里程碑

1. 以已完成的麦镇手工样本为基线，迁入正式地图工具链并补齐独立室内、事件与环境叙事，验证内容能否无损往返编辑。
2. 增加敌人技能、弱点、异常状态和 Boss 阶段，避免只靠数值增长维持战斗。
3. 在已完成四向轮廓、炮塔瞄准/后坐和 SP 受损反馈的基础上，制作原创逐帧底盘、履带、部件损坏和瘫痪残骸动画。
4. 增加多存档槽、存档版本号、迁移测试与损坏回退。
5. 在已完成独立音量与文本速度的基础上，增加键位、手柄映射与无障碍设置。

### P2：内容扩展与打磨

1. 天候、昼夜、环境音与区域色调，但不得牺牲地图辨识度。
2. 更完整的赏金情报、任务状态、图鉴和战车比较界面。
3. 性能预算、资源分包、低端移动设备回归与长时间内存测试。
4. 发布包、署名、隐私说明、版本更新和崩溃诊断流程。

## 5. 下一轮实施顺序

1. 冻结当前拉多纵切的状态、存档和地图层契约，补一条端到端基准流程。
2. 用一张小型测试地图完成 Phaser 3 + LDtk/Tiled 的加载、碰撞、对象触发、前景遮挡和相机验证。
3. 将麦镇数据迁入测试管线，确认现有手工布局、碰撞、对象与存档坐标可以无损往返。
4. 同步制作一辆原创战车、一组原创敌人和一首 FamiStudio 场景曲，验证三条内容管线。
5. 只有当麦镇在正式工具链内达到拉多同等或更高验收标准后，才批量扩展其余区域。

## 6. 发布门槛

满足以下条件前，不应对外称为“完整游戏”：

- 所有正式剧情、角色、地名和视觉资产完成原创化与许可审查。
- 每座城镇和迷宫逐张通过可达性、碰撞、交互、地标、截图和音乐验收。
- 主线、自由探索、战车收集、赏金循环和结局完成连续通关测试。
- PC、主流移动端和手柄流程均有自动化与真实设备证据。
- 音乐拥有可编辑工程源、清晰循环点和统一响度；第三方归属随发布物提供。
- 存档具有版本迁移、损坏恢复和发布版本回归测试。
