# FC 风格废土 RPG 生产基线

这份文档定义《荒原引擎》的场景生产门槛。目标不是复刻任何受版权保护的素材，而是保留 FC 时代俯视角 RPG 的信息密度、可读性和探索节奏，并使用原创或许可清晰的资源。

## 1. 画面与输入

- Pixi 场景画布必须覆盖完整可视区域，不允许用 `640x480` 外框限制世界画面；探索瓦片基础尺寸为 `32px`，战斗虚拟构图为 `1280x720`。
- Vue 窗口使用独立 `640x480` 可读安全区，不能反向限制 Pixi 相机与背景范围。
- 渲染缓冲按设备像素比建立（当前上限 2×）；所有像素纹理必须使用 nearest-neighbor 采样。
- 必须验收 `1366x768`、`1920x1080`、`2560x1440`、`390x844` 与 `844x390`，PC 页面不能长期锁死在 `640px` 宽。
- 玩家移动期间相机必须按像素跟随，不能按整格跳动。
- 键盘、手柄和触屏必须覆盖同一套确认、取消、移动能力。
- 战车探索表现必须提供四个真实朝向，炮管、底盘和行驶方向一致；不得用同一张侧视图翻转冒充上下方向。

## 2. 地图层协议

每张正式地图至少具备以下语义层；Pixi 容器、纹理生成与规则数据必须保持职责分离：

1. `ground`：基础地表。
2. `path`：道路、地表过渡和足迹。
3. `below`：地毯、阴影、低矮碎屑。
4. `collision`：不可通行区域，必须由数据驱动。
5. `trigger`：门、宝箱、剧情、场景切换。
6. `entity`：玩家、NPC、战车和敌人，按脚底 Y 排序。
7. `above`：屋檐、树冠、门框等前景遮挡。
8. `light`：灯光、天气和局部色调。

渲染与碰撞不得分别随机生成同一个物体。看到的实体必须有一致的碰撞和交互定义。

## 3. 城镇验收

- 每座城镇拥有独立轮廓、主地标、服务区、住宅区和出入口动线。
- 关键建筑必须可进入；纯装饰建筑应通过门牌、锁门反馈或环境叙事说明用途。
- 每屏至少存在一个方向性地标，玩家不能只靠 HUD 判断位置。
- NPC 对话应提供世界观、路线、玩法或事件状态中的至少一种有效信息。
- 禁止通过同一套建筑坐标换颜色生成多个城镇。

## 4. 角色与空间

- 主要角色至少四方向、每方向三帧：站立、左脚、右脚。
- 所有实体使用脚底锚点和脚底碰撞盒。
- 同层实体按 Y 排序；高物件必须提供前景遮挡层。
- NPC、玩家与装饰物不能互相穿透。

## 5. 纵切范围

第一个生产纵切包含：

- 父亲的修理店室内与开局剧情。
- 手工设计的拉多镇。
- 武器店、战车工房、宿屋、情报屋四类室内。
- 拉多南洞窟、NO.1 战车获取和一次完整战斗。
- 存档、读档、键盘和触屏流程。

只有纵切通过实机截图、碰撞路线、关键交互和性能验收后，才扩展其余城镇。

## 6. 工具路线

- Vue 3：HUD、菜单、对话和商店窗口。
- PixiJS 8：正式承接场景图、全屏相机、实体排序、天气、灯光和战斗特效。
- Tiled 或 LDtk：人工地图与对象层。
- Aseprite：角色、战车、敌人和 tileset 源文件。
- 浏览器 QA：桌面/移动端实机截图、WebGL 画布非空、DPR 缓冲尺寸和关键路径回归。

PixiJS 已成为正式运行时；旧 Canvas renderer 只保留离线预览兼容，不得重新接回每帧游戏循环。后续场景升级不得改变游戏状态和存档协议。

## 7. 当前完成边界

截至 2026-08-03，只有以下内容可以按“第一纵切”验收：父亲修理店、拉多镇、四类服务室内、拉多南洞、首辆战车获取、一次完整战斗，以及对应的键盘/触屏流程。麦镇已作为第二个手工城镇样本完成布局与视觉验收，但独立室内、完整事件和正式地图工具链尚未闭环。

其余城镇、洞窟和终局流程虽然已有数据与可运行逻辑，但仍大量复用程序化布局和临时美术，不得按正式内容对外宣称完成。批量扩展正式区域前，应完成 Tiled/LDtk 地图生产管线、原创角色/敌人/战车资产规范，以及带 intro/loop 标记的音乐制作管线。
